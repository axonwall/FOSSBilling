- Config aliases normalized by `normalizeDriver()`: `mysql` → `pdo_mysql`, `mariadb` → `pdo_mysql`, `pgsql` → `pdo_pgsql`, `postgres` → `pdo_pgsql`, `postgresql` → `pdo_pgsql`, `sqlite` → `pdo_sqlite`, `sqlite3` → `pdo_sqlite`.
- MySQL/MariaDB charsets: `utf8`, `utf8mb4`, `latin1` (default utf8mb4).
- **Fresh-install schema is generated from Doctrine entity metadata on every driver** (SchemaInstaller/SchemaTool) — which is exactly why this entity map is the schema of record for the strangler, and a Drizzle schema can be generated from the JSON twin of this file for MySQL **or** Postgres from the same source.
- Upgrades: UpdatePatcher::applyCorePatches() runs SchemaSynchronizer (additive only: new tables/columns/indexes; never drops/alters, no FKs added to pre-existing tables) after MySQL/MariaDB-only legacy patches; historical data transformations in those legacy patches never replay on other drivers.

## Strangler notes

- Cross-module coupling is deliberately loose: many modules store other modules' ids as plain `BIGINT` columns instead of relations (e.g. `support_ticket.client_id`, `invoice.client_id` are plain columns; relations exist mainly *within* a module). Porting module-by-module therefore does not require porting the whole relation graph at once.
- Money tables live in Invoice (`invoice`, `invoice_item`, `transaction`, `subscription`, `tax`, `pay_gateway*`) + Client (`client_balance`) + Product (`product_payment*`) — the Phase 3 set from the conversion plan.
- `transaction` is a reserved word: the entity maps it backtick-quoted (`#[ORM\Table(name: '`transaction`')]`); the JSON records it unquoted as `transaction`.
